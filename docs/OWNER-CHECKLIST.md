# ١. الاستيعاب — ينقل المصفوفة من 11 إلى 15

## لماذا لا أفعله أنا

بيئتي محجوبة عن `qurancomplex.gov.sa`. جرّبتُها وردّت:

```
{"status":"SOURCE_PAGE_UNREACHABLE","reason":"HTTP_403"}
```

وهذا حاجزُ شبكةٍ لا عطلُ شيفرة — السكربت وصل إلى الشبكة فعلًا.

## ١.أ — من Cloud Shell (الأيسر)

افتح [Cloud Shell](https://console.cloud.google.com/) بأيقونة `>_` أعلى اليمين، ثم:

```bash
cd ~ && git clone https://github.com/ProfAlfailakawi/Mizan.git && cd ~/Mizan && npm ci
```

> المستودعُ عامّ فلا يحتاج تسجيل دخول. الاستنساخ ٣٤ ميغابايت، و`npm ci` نحو **١٫١
> غيغابايت** — قِيست بالقياس لا بالتقدير. وذاكرةُ Cloud Shell ٥ غيغابايت فتسعها.

**وإن قال `destination path 'Mizan' already exists`** فالمجلّد موجودٌ من محاولةٍ سابقة:

```bash
cd ~/Mizan && git pull --ff-only origin main && npm ci
```

ثم — **هذا الأمر وحده**:

```bash
cd ~/Mizan && npx --yes tsx scripts/kfgqpc-acquire.ts
```

**ما تراه إن نجح:** تسعة أسطر JSON، كلُّ سطرٍ فيه `"status":"ACQUIRED_VERIFIED"`.

**ما تراه إن فشل:** سطرٌ فيه `SOURCE_PAGE_UNREACHABLE` أو `NOT_ACQUIRED`، والأمرُ يخرج
بالرمز 2 (صار يفشل صراحةً بعد إصلاح 19 سبتمبر — كان قبلَه يخرج صفرًا فيبدو ناجحًا وهو فاشل).

**أرسل لي:** المخرجات كاملةً كما هي.

## ١.ب — لا تُشغّل الأمر الثقيل

```
✗ npx tsx scripts/kfgqpc-heavy-acquire.ts --full
```

سقوفُ تحميله تتجاوز **٢٠ غيغابايت** (صوتُ السوسي وحده ٥). سيملأ القرص ويتوقّف في المنتصف.
وهو **غيرُ لازمٍ** لما نريد: عمودُ البصمة في المصفوفة مصدرُه الحزمُ الخفيفة وحدها، سقفُ
كلِّ واحدةٍ منها ٦٤ ميغابايت.

## ١.ج — لماذا لا تنفع بوّابةُ GitHub الآن

سيرُ `kfgqpc-ingest.yml` يُشغّل الخفيفَ ثم **الثقيلَ** ثم التحقّق. والثقيلُ فشل في آخر
تشغيل (18 سبتمبر) بـ`REQUIRED_OFFICIAL_ASSETS_NOT_ACQUIRED` فأوقف الوظيفةَ قبل خطوة التحقّق.

فلا تُشغّله الآن. وإن أردتَ استعمالَه لاحقًا: **`dry-run` فقط**، ولا تختر `publish` إلا
بكلمةٍ صريحةٍ منك لي — فهو يكتب في تخزين الإنتاج كتابةً لا تُردّ.

## ٣.د — المتغيّرات السبعة

تُضاف إلى `--update-env-vars` في `cloudbuild.yaml` (ليست أسرارًا):

```bash
MIZAN_LEGAL_ENTITY_NAME="شركة سكاي جيت للإستشارات التربوية"

MIZAN_LEGAL_TERMS_URL="https://.../terms"
MIZAN_LEGAL_TERMS_VERSION="1.0"
MIZAN_LEGAL_TERMS_EFFECTIVE="2026-10-01"

MIZAN_LEGAL_PRIVACY_URL="https://.../privacy"
MIZAN_LEGAL_PRIVACY_VERSION="1.0"
MIZAN_LEGAL_PRIVACY_EFFECTIVE="2026-10-01"
```

**والسبعةُ كلُّها أو لا شيء.** رابطٌ بلا نسخة، أو نسخةٌ بلا تاريخ سريان، يبقى
`LEGAL_DOCUMENT_NOT_PUBLISHED` — فلا يُعرف على أيِّ نصٍّ وقَّع الموقِّع ولا متى صار ساريًا.

> **وقاعدةٌ لا تُكسر بعد النشر:** إن عدّلتَ نصَّ وثيقةٍ منشورة فارفع رقمَ النسخة وتاريخَ
> السريان. ولا تُعدّل نصًّا تحت رقمٍ قائم أبدًا: موافقةُ من سجّل أمسِ مسجّلةٌ بـ«١٫٠»،
> فإن تغيّر نصُّ ١٫٠ صار السجلُّ يشهد على ما لم يره.

# ٥. كيف تتحقّق بنفسك في أيّ وقت

من داخل `~/Mizan`:

```bash
npm run preflight
```

**⚠️ واقرأ هذا قبل أن تُفزعك نتيجتُه.** هذا الأمر يقرأ **متغيّرات الصدَفة التي تُشغّله
فيها** (`process.env`) — لا Cloud Run ولا Secret Manager. ففي نسخةٍ طازجةٍ في Cloud Shell
سيقول «٥ موانع» **ولو أتممتَ كلَّ شيء**، لأن تلك الصدَفة لا تحمل إعدادَ الإنتاج. فهو يجيب
عن «هل بيئتي هنا مضبوطة؟» لا عن «هل الإنتاج جاهز؟».

**وللسؤال الثاني بوّابةٌ أخرى، وهي التي يُعتمد عليها:**

GitHub ← Actions ← **«بوّابات الإطلاق — ما يحتاج أسرارًا»** ← Run workflow

فهي تُشغَّل بأسرار المستودع وتقرأ `cloudbuild.yaml`، فتحكم على **ما يُنشر فعلًا**.
وتعمل يوميًّا 04:17 UTC، والتشغيلُ اليدويُّ متاحٌ في أيّ وقت.

> وحمرتُها اليومَ متوقَّعة بالموانع الأربعة نفسها. والمقصودُ أن **سببَها** يتغيّر كلّما
> أتممتَ بندًا — فاقرأ الأسماء لا اللون.

```bash
npx tsx scripts/quran-release-matrix.ts
```
يطبع `release-ready` من أصل 20، ويُسمّي ما لم يكتمل وسببَه.

```bash
npm run check
```
البناءُ والاختباراتُ كاملة — **2087 اختبارًا**: 2076 ناجحًا، صفر فاشل، و11 متخطًّى
بشرطِ بيئةٍ غائبة (محاكي Firestore) لا إخفاءً لفشل.

> لا تُصدّق رقمًا في محادثة. هذه الأوامرُ تقرأ الشجرةَ وتحسب، ولا تنقل من ذاكرة.
