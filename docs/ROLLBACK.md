# التراجع — ما الذي يُرجَع، وكيف، ومتى

> هذه وثيقةُ تشغيل. تُقرأ وقت العطل، لا قبله. فكلُّ خطوةٍ فيها أمرٌ يُنفَّذ لا وصفٌ يُفهم.

---

## 0. القاعدة التي تُنسى أولًا

**لا تُبدَّل بيانات القرآن في نشرةٍ صامتة.** النشرةُ التي تغيّر `quranDataVersion` أو
`crosswalkVersion` تغيّر معنى كل نتيجةٍ سُحبت تحتها. فإن تغيّر أحدُهما فذلك حدثُ إصدارٍ
يُعلَن ويُوثَّق، لا تفصيلٌ في سجلّ نشر.

وكلُّ جلسةٍ تحمل الإصدارات التي فُسِّرت بها (`server/secure-question-runtime.ts`):

| الحقل | من أين يأتي | ما الذي يفسّره |
|---|---|---|
| `appVersion` · `buildId` | `dist/build-id.json` أو `BUILD_ID` | الشيفرةُ التي كانت تعمل |
| `quranDataVersion` | `DELIVERY_COUNT_EVIDENCE_BUILD.generatedArtifactSha256` | ترقيمُ الآي المقيس الذي بُني عليه |
| `crosswalkVersion` | `COMMITTEE_CROSSWALK_VERSION` | جدولُ الجسر القانوني ↔ الأصلي |
| `algorithmVersion` · `ruleVersion` | ثابتٌ في محرّك السحب | خوارزميةُ القرعة وسياستُها |
| `sourcePackageId` · `sourcePackageHash` | بيانُ الحزمة | بايتاتُ النصّ بعينها |

فإعادةُ تفسير نتيجةٍ قديمة لا تحتاج ذاكرةَ أحد: تُقرأ هذه الحقول من الجلسة نفسها.

---

## 1. تراجعُ التطبيق (`appVersion` · `buildId`)

أسرعُ ما يُرجَع وأقلُّه أثرًا: الصورةُ السابقة على Cloud Run.

```bash
gcloud run services update-traffic <service> --to-revisions=<previous-revision>=100
curl -s https://<host>/api/version      # يجب أن يعود buildId السابق
```

**ما لا يتراجع معه:** ما كُتب في قاعدة البيانات أثناء عمل النسخة الجديدة. فإن كانت
النشرةُ حملت هجرةَ مخطَّط، اقرأ §4 قبل التراجع.

---

## 2. تراجعُ بيانات القرآن (`quranDataVersion`)

أعدادُ الآي مقيسةٌ من بايتاتٍ مثبَّتة ومجمَّدة في المستودع
(`quran-sources/delivery-counts/kfgqpc-mirror/`). فالتراجع هنا **تراجعُ شيفرة**:

```bash
git revert <commit>                      # الذي غيّر counts.json أو المولَّد
npm run quran:delivery-counts -- --clone=<checkout of the pinned mirror commit>
npm run quran:release-matrix             # يجب أن تعود الأرقام إلى ما كانت
```

**فحصُ القبول:** `quranDataVersion` في جلسةٍ جديدة يساوي قيمتَه قبل النشرة.

**ولا يجوز** تعديلُ `counts.json` يدويًا لإعادة رقمٍ إلى ما كان: الأرقام مقيسةٌ من
بايتات، وتعديلُها يدويًا يجعلها دعوى.

---

## 3. تراجعُ جسر المواضع (`crosswalkVersion`)

الجسرُ مولَّدٌ من أثرٍ مثبَّتٍ ببصمته، فتراجعُه تراجعُ التثبيت:

```bash
git revert <commit>                      # الذي غيّر quran-count-boundary-source.ts أو المولَّد
npm run quran:crosswalk-activate         # يعيد التوليد ويطبع ما فُعّل وما حُجب
npm run quran:release-matrix -- --markdown
```

**ما ينتبه له المشغّل:** التراجعُ قد يعيد رواياتٍ إلى «غير جاهزة للسؤال». فإن كانت
مسابقةٌ مفتوحة على إحداها، فحصُ ما قبل الانطلاق سيمنعها **بالاسم** — وهذا مقصود، لا عطل.

---

## 4. هجرةُ المخطَّط (`schema`) — الأمام أولى من الخلف

هجرةُ البيانات لا تُرجَع بالتراجع عن الشيفرة وحدها: النسخةُ القديمة قد لا تقرأ ما كتبته
الجديدة. فالقاعدة:

1. **كلُّ هجرةٍ تُكتب متوافقةً للأمام**: الحقلُ الجديد اختياري، والقديمُ لا يُحذف في نفس
   النشرة التي تتوقّف عن كتابته.
2. الحذفُ يقع في نشرةٍ **تالية** بعد أن يثبت أن لا شيء يقرأه.
3. وعند العطل: **أصلح للأمام** (نشرةٌ صغيرة تُصحّح) بدل التراجع، ما دامت الجديدة تكتب
   ما تقرؤه القديمة.
4. والتراجعُ عن هجرةٍ حاذفة لا يُستعاد إلا من نسخةٍ احتياطية — راجع `docs/BACKUP-RESTORE.md`.

---

## 5. ترتيبُ التراجع عند عطلٍ مركَّب

من الأقلّ أثرًا إلى الأكثر، ويُتوقَّف عند أول ما يُصلح:

1. تحويلُ الحركة إلى النسخة السابقة (§1) — ثوانٍ، وبلا فقد.
2. تراجعُ الجسر أو بيانات القرآن (§2/§3) — إن كان العطلُ في الجاهزية أو في موضعٍ معروض.
3. إصلاحٌ للأمام في المخطَّط (§4).
4. الاستعادةُ من نسخةٍ احتياطية — آخرُ ما يُلجأ إليه، وله وثيقتُه.

---

## 6. بعد كل تراجع

```bash
npm run quran:release-matrix
npm run preflight
```

وسجّل في سجلّ الإصدار: ما رُجع، ومن رجّعه، ومتى، وما الذي عاد إلى ما كان — ولا يُغلق
العطلُ قبل أن يُقرأ `/api/version` ويطابق المتوقَّع.
